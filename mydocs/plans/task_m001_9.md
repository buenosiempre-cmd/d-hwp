# D-HWP 구성원 문서 활용 업그레이드 수행계획서

Issue: [#9](https://github.com/buenosiempre-cmd/d-hwp/issues/9), M001

## 목적과 승인 근거

사용자의 “구성원들이 쓰기에 추가되거나 업그레이드 하면 좋을 기능들도 검토해서 업그레이드 하자” 및 앞선 구현·커밋·푸시 지시에 따른다. Slack 중심 제품 방향과 원하는 채널에 초대하여 쓰는 방식을 유지한다. 기존 일반 배포 승인은 유지하되, 실제 Slack 신규 권한 부여는 별도 확인 대기 중이다.

## 우선순위와 범위

설문 결과가 아닌 기존 기능 공백과 행정 문서 활용 예시에 근거한 판단이다. 필요한 쪽의 공지·회의자료 이미지를 받는 선택 쪽 PNG ZIP, 본문 재사용을 위한 원문 TXT, 명령어 없이 쓰는 형식·쪽 선택 메뉴를 우선 구현한다.

- 1~200쪽 중 최대 10쪽, 쉼표·구간 선택 지원. 실제 문서를 벗어나면 전체 요청 실패, 임의 절단 금지.
- 기존 PNG 5 MiB/쪽·합계 25 MiB, ZIP 26 MiB, TXT 2 MiB 제한. 원문·산출물·비밀값은 Git에 넣지 않는다.
- 기존 앞 3/10쪽 갤러리와 독립된 내보내기 영수증 사용. 권한·원본 hash 재확인 및 중복 업로드 방지. 문서당 서로 다른 내보내기 최대 20개.
- 로컬 및 Cloud 경로 모두 연결. 기존 명령어 문법은 유지하고 새 기능은 카드 메뉴에서 제공한다.
- 원문 TXT는 그림·수식·OCR·표 배치 복원을 의미하지 않는다.
- 전체 원문 검색, 표→Excel, OCR, 실제 AI 요약 및 MCP 규정 검토 확대는 후속 과제로 판단 근거와 한계를 기록한다.

## 문서 위치와 단계

사용자·운영자 문서는 기존 README와 docs/를 확장한다. mydocs/에는 계획·진행·검증 근거를 둔다. 별도 사이트 문서 루트는 만들지 않는다. 사용자가 요청한 기능 검토 결과는 작업 폴더에 독립 HTML로 제공한다.

1. 변환 엔진: TXT, 선택 쪽 PNG와 ZIP, 경계·실제 엔진 검사.
2. Slack: 내보내기 메뉴, 사용자 바인딩·권한·복구, 로컬/Cloud 통합 검사.
3. 문서·검증·Git 게시: typecheck, 관련 unit/Slack/security/engine 검사, 원격 SHA 확인 및 PR.

## 원복과 검증 한계

기존 운영 RHWP, MCP, 웹 데스크와 터널은 변경하지 않는다. 새 소스는 기능 검증 후 별도 커밋으로 게시한다. 실제 Slack 설치·워크스페이스 파일 업로드가 완료되지 않으면 로컬·CI 검증과 명확히 구분하여 보고한다.
