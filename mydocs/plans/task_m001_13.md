# Task #13 — 공개 문서 검증 루프와 추출 품질 보강

GitHub Issue: [#13](https://github.com/buenosiempre-cmd/d-hwp/issues/13). 내부 분류 M001. live milestone 없음, 기존 enhancement label 사용.

## 목적과 배경

사용자의 “계속 업그레이드 하고 점검하고 루프검증해서 완성해” 지시를 실행한다. #11의 구조 Markdown·Kordoc 대조 위에서 공개 포맷 문서 다양성과 누락/왜곡 경계 사례를 더 검증하고 재현된 결함을 수정한다. 현재 PR #12의 push·PR viewer/container CI는 모두 성공했다. 실제 Slack 앱은 자격 증명 설정·권한 확인이 남아 있다.

## 승인과 기준

현재 사용자의 계속 진행 지시와 기존 구현·커밋·푸시·배포 지시에 따라 작업 단계를 계속한다. 저장소 규칙의 신규 승인 반복은 추가로 요청하지 않는다. 대기 중인 앱 권한 부여를 임의 완료로 처리하지 않는다. 기존 task11 미병합 변경에 의존하므로 확인된 HEAD d8dbf99에서 local/task13을 만들고 publish/task11 기준 PR을 사용한다.

## 범위와 설계

- 공개 RHWP/Kordoc 시험 문서를 출처·고정 커밋·해시와 함께 검사. 원본 다운로드는 .cache, 재배포 조건 확인 전 Git에 넣지 않음.
- 독립 감사의 재현 결함을 수정하고 회귀 검사 추가. XML 텍스트 대응과 실제 의미 완전성을 구분.
- Kordoc 로컬 OCR 실제 결과와 운영 적용 가능성 평가. 모델을 고정하고 원문 외부 전송 없이 사용할 수 있는 경우에만 통합하며, 추측/실패를 숨기지 않음.
- Linux network-none/read-only 운영 조건에서 Markdown package 실제 변환을 smoke 검사에 포함.
- 변환 품질·검토 안내를 구성원이 이해할 수 있게 보강하고 반복 검사 명령 제공.
- 기존 RHWP·규정 MCP·웹 작업실 프로세스 및 사용자 원본 보호. 임의 PR merge/issue close 제외.

## 문서 위치 판단

사용자 범위·검토 항목·Kordoc/OCR 설명은 기존 docs/d-hwp-markdown.md, 운영 내용은 docs/d-hwp-slack.md에 반영한다. 코퍼스 출처 manifest/검증 스크립트는 tests 및 scripts에 둔다. 작업 계획/단계/최종 근거는 mydocs에, 독립 HTML 보고서는 작업 폴더에 둔다.

## 단계와 검증

1. 공개 코퍼스·독립 감사·OCR 실측으로 발견→재현. 고정 출처와 기대값 구분.
2. 확인한 결함/품질·운영 공백 구현. 관련 회귀→실제 HWP/HWPX→Kordoc 비교.
3. 독립 재검토 후 필요한 범위만 재검사. 전체 typecheck/unit/Slack/security/conversion 및 GitHub CI를 확인하고 commit/push/PR/원격 SHA 보고.

반복 종료 기준은 선정한 코퍼스와 재현 경계 사례에 알려진 블로커가 없고 코드 변경 후 필요한 검사/독립 재검증/CI가 통과하는 것이다. 이것을 모든 문서의 무누락 또는 실제 Slack 설치 성공으로 확대하지 않는다.
