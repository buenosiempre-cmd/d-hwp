# D-HWP Slack 문서 변환 수행계획서

Issue: [#7](https://github.com/buenosiempre-cmd/d-hwp/issues/7), M001

## 목적과 승인 근거

사용자의 “rhwp를 동국화”, “한글문서를 이미지 피디에프 마크다운 문서등으로 변환”, “슬랙에서 쓸수있게” 지시에 따라 Slack 중심 제품으로 수정한다. 설치 대상은 사용자가 선택한 동국대 재무팀이다. 앞선 구현·커밋·푸시·배포 지시 범위의 작업을 계속 진행한다.

## 범위와 문서 위치

- 기존 PDF·PNG 및 RHWP 편집 기능을 유지하면서 실제 원문 Markdown 변환과 Slack 결과 선택을 추가한다.
- 원본 파일 권한을 요청과 업로드마다 확인하고 비밀값·원본 문서·결과물을 Git에 넣지 않는다.
- 사용자의 후속 지시로 채널 사전 지정은 하지 않는다. 봇 초대를 확인하면 해당 채널을 활성화하고 기존 관리자 off/mention 설정은 유지한다.
- 기존 /rhwp 호환 처리 유지. 기존 설치와 충돌하지 않도록 D-HWP 신규 manifest에는 /dhwp를 등록한다.
- 엔진은 RHWP 0.8.7 별도 의존성으로 유지한다. 무제한 이미지·ZIP·OCR는 이 범위에 포함하지 않는다.
- 사용자·운영자 문서는 기존 README 및 docs/에 둔다. mydocs는 내부 계획·검증 근거만 보관한다. 대안인 별도 site/는 중복 안내를 만들므로 사용하지 않는다.
- 실제 Slack 앱 설치·검증은 로컬 검사와 구분하며 자격 증명이나 로그인 부족 시 사실대로 기록한다.

## 단계와 수용 기준

1. 변환: HWP/HWPX 원문 Markdown 생성, 크기·시간 제한 및 오류 검사.
2. Slack: D-HWP 안내·PDF/이미지/Markdown 버튼, 명령 및 안전한 같은 스레드 업로드, 로컬/Cloud 연결.
3. 배포·검증·게시: 앱 manifest/설치 흐름, 적절한 테스트·빌드·문서, Git 원격 확인 및 PR.

## 검증과 원복

관련 conversion·Slack·security 검사와 typecheck/build를 실행한다. 합성 문서로 실제 엔진 출력과 버튼 결과를 확인한다. 기존 운영 앱·터널을 임의 제거하지 않는다. 새 배포가 실패하면 신규 D-HWP Slack 서비스만 중지하고 기존 기능을 유지한다.
