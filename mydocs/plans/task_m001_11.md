# Task #11 — 문서 내용 보존 Markdown 수행계획서

Issue: [#11](https://github.com/buenosiempre-cmd/d-hwp/issues/11), M001

## 요구와 승인

사용자는 한글 문서의 모든 내용을 Markdown으로 파악할 수 있어야 하며 빠짐이 없어야 한다고 지시했다. 기존 Unicode 본문 추출에서는 머리말·꼬리말·각주·미주·수식이 실제로 누락된다. 이 문제를 수정하고 앞서 승인된 구현·커밋·푸시를 계속한다.

## 구현 방향

- 원본 HWPX는 ZIP 내부의 구조 XML을 직접 읽고 spine 순서를 따른다. HWP는 RHWP `exportHwpxWithReport`의 구조 변환과 content-loss 보고서를 함께 읽는다. 구조 손실을 숨기지 않는다.
- 단락·표의 행/열·병합·중첩, 각주/미주, 머리말/꼬리말, 글상자, 수식 원문, 링크 정보, 그림과 기타 개체를 구분하여 Markdown에 기록한다. 알 수 없는 텍스트·개체는 무시하지 않고 원문 구조/검토 항목으로 보존한다.
- `.md` 단독 결과와 더불어 Markdown·이미지·원본·기계 판독 대조 보고를 담은 ZIP 패키지를 Slack에서 제공한다. 그림은 실제 자산을 보존하며 OCR/시각 의미를 텍스트로 이해했다고 주장하지 않는다.
- 원본의 요소·텍스트와 출력 대응을 검사하고 미지원·손실·누락 의심·이미지 OCR 미처리는 명시한다. 엔진 손실 보고 0을 모든 내용 보존의 증명으로 취급하지 않는다.
- 크기/깊이/노드/압축 해제 한도와 CRC 검증, DTD·외부 entity·경로 traversal 거부, Markdown의 임의 HTML/외부 자동 로딩 방지를 적용한다. 한도 초과는 임의 절단 대신 실패 처리한다.
- 기존 카드의 이전 텍스트 Markdown 영수증을 새 구조 출력으로 오인하지 않도록 버전 구분을 둔다. 로컬·Cloud 권한 및 업로드 복구를 유지한다.

## 문서 위치와 단계

기존 README와 docs/에 사용자·운영 설명을 갱신하고 `docs/d-hwp-markdown.md`에 패키지와 Kordoc 비교 범위를 기록하며 mydocs/에 구현·검증 기록을 둔다. 독립 HTML 보고서는 작업 폴더에 제공한다.

1. 안전한 ZIP/XML 처리, 구조 추출·이미지/개체 목록·대조 보고, 실제 복합 fixture 검증.
2. 격리 변환 프로토콜과 Slack Markdown/패키지 연결, 기존 영수증 버전 호환.
3. typecheck·unit·Slack·security·실제 변환·독립 리뷰, 보고·원격 SHA 확인·PR.

## 수용과 한계

합성 HWP/HWPX의 본문·표·머리말·꼬리말·각주·미주·글상자·수식 등의 sentinel과 순서/구조를 대조한다. Markdown만으로 원본의 모든 시각 배치를 동일하게 표현할 수는 없으므로 원본과 자산을 함께 제공하고, 실제 추출 범위와 확인 불가능 항목을 표시한다. 알려진 누락을 남긴 채 ‘100% 완전 변환’으로 표시하지 않는다. Slack 설치 권한 확인은 기존 대기 상태와 구분한다.

## 추가 품질 요구 반영

사용자는 Kordoc 참조 또는 연계 여부를 확인했다. 연결된 Kordoc MCP와 로컬 4.19.1을 같은 합성 HWP/HWPX에 실행하고 독립 비교 스크립트를 남긴다. 운영 의존성으로 추가하지 않으며 Kordoc 결과를 무조건 정답으로 합치지 않는다. 문서 파싱 결과를 명령으로 실행하지 않는다.
