# Task #13 Stage 2 — 검토 안내와 오프라인 OCR

ZIP에 README.md를 추가해 문서 읽기 순서·규모·검토 항목을 짧게 안내한다. 전체 Markdown·report.json·원본·이미지·HWP 해석 구조는 유지한다.

로컬 Kordoc 4.19.1의 실행 파일 70개/진입 파일과 OCR 모델 3개의 SHA를 확인한 뒤, 자격 증명이 없는 별도 프로세스에서 인식한다. Offline 설정과 fetch 차단, 5 MiB·16Mpx·10개·60초 한도, 원본 이미지 보존과 이스케이프한 보충 텍스트를 적용한다. Native 처리는 SIGKILL로 중단하며 상위 프로세스 그룹의 취소도 상속한다. 시작 시 프로필을 검사하고 OCR 소스 해시도 runtime manifest에 포함했다.

서버 환경의 두 경로만 OCR 실행을 선택한다. Slack 요청은 모듈 경로를 지정할 수 없다. markdown-v3와 markdown-v3-ocr로 이전 영수증과 구분한다. 독립 리뷰에서 OCR 환경 실패 패키지의 영구 재사용 문제를 재현했다. 이를 수정해 환경·시간 제한 실패 시 업로드하지 않고 빈 영수증을 제거한다. 로컬·Cloud 모두 같은 카드의 장애 복구 후 재처리와 성공 결과 재사용을 검증했다.

합성 한글 그림을 포함한 HWP/HWPX 전체 변환에서 각각 OCR 1개 성공, 검사 문구 4/4(공백 제외), 원본·이미지의 동일 바이트를 확인했다. macOS arm64/Node 24.21.0에서 HWP 1.722초, HWPX 0.980초였으며 단일 시험 시간이지 서비스 SLA는 아니다. 공백 오류가 있어 항상 검토 대상으로 표시한다. GIF·다중 프레임·미지원 개체와 문서의 자르기·회전·배치는 OCR 해석 범위 밖이다.
