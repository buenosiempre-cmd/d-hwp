# Task #9 Stage 2 — Slack 통합

## 구현

기존 카드에 형식·쪽 선택 버튼과 5분 유효 모달을 추가했다. TXT와 PNG ZIP을 같은 스레드에 공유한다. 메뉴와 선택 ID는 요청자의 팀·사용자·카드·메시지에 연결한다. Cloud는 최초 선택을 atomic하게 고정하고 durable enqueue를 마친 뒤 ACK한다.

기존 갤러리와 별도의 정규화 키·업로드 영수증을 사용하며 카드당 서로 다른 내보내기 20개로 제한했다. 실패한 변환은 빈 슬롯을 회수하지만 이미 할당한 업로드는 보존한다. 동일 선택 동시 요청, 완료 응답 유실, 재시작 후 같은 선택 재요청에서 업로드를 중복하지 않는다.

변환 전후 권한과 원문 hash, 업로드 공유 직전 권한을 확인한다. TXT UTF-8·출력 크기와 ZIP 서명·쪽 목록·실제 쪽수·출력 크기도 확인한다. source hash가 없는 이전 카드에는 첫 내보내기 전에 hash를 고정한다. hash 없이 이미 할당된 영수증이 있으면 다른 형식으로 요청해도 사용을 거절한다. 독립 리뷰에서 발견한 같은 크기의 원본 변경 후 과거 결과 재사용 문제를 이 방식으로 수정했다.

## 검증

Node 24.21.0에서 최종 `npm run typecheck` 및 `npm run test:slack` **285/285** 통과.

새 검사는 실제 서명된 interaction 요청의 모달·제출 흐름, 사용자·팀·메시지 변조, TTL, 권한 회수, 원래 스레드 업로드, 선택별 영수증, 재시작 복구, 원문 변경과 이관 카드를 포함한다. Cloud 코드와 로컬 코드에 대해 독립 읽기 리뷰를 수행했다.

앱 홈·환영 메시지·설정·manifest의 설명을 함께 갱신했으며 신규 Slack 권한을 추가하지 않았다. 실제 워크스페이스 메시지는 보내지 않았다.
