# Task #7 결과 — D-HWP Slack 문서 변환

## 결과

사용자의 방향 수정에 맞춰 D-HWP를 Slack에서 쓰는 RHWP 확장으로 정리했다. 원하는 채널에 앱을 초대하면 활성화되고 HWP/HWPX를 PDF·앞 10쪽 PNG·원문 텍스트 Markdown으로 받을 수 있다. RHWP 편집 연결은 유지했다. Markdown은 AI 요청문이 아니라 실제 문서 추출 결과다.

## 검증

| 대상 | 결과 |
|---|---|
| TypeScript | 앱·서버·테스트 타입 검사 통과 |
| 단위 검사 | 37개 통과 |
| Slack | 전체 252개 + 추가 재시작 회귀 2개 통과 |
| 보안 | 91개 통과 |
| 후속 변경 집중 검사 | 서명 요청·권한·초대·명령·변환 19개 통과 |
| 실제 RHWP 엔진 | Markdown/프로토콜/실패 13개와 기존 PDF·PNG 실렌더 10개 통과 |
| 실행 자산 | Node 24.21.0·의존성·Chromium·정적/변환 해시 등 7개 통과 |
| manifest | bootstrap 및 최종 URL 생성, /dhwp 단독 등록 확인 |
| 실제 Slack | 앱 생성/설치 권한 확인 단계, 업로드 실검증 미완료 |

파일 권한 회수, 잘못된 팀·앱·채널·카드 메시지, 변환 중 권한 변경, 동시 재요청과 완료 응답 유실을 검사했다. 문서 bytes·업로드 signed URL은 상태 DB에 보관하지 않는다.

## 배포 상태와 남은 작업

동국대 재무팀의 Slack 앱 설치 검토 화면을 준비했다. 새 앱의 파일 읽기/쓰기·채널 정보·멘션·메시지·반응·명령 권한 부여 전 사용자 확인이 필요하다. 확인 후 앱 생성/설치, 외부 비밀 설정, 별도 HTTPS 실행, 실제 채널 초대 및 합성 문서 변환을 진행한다. 코드 검사 결과를 실제 설치 성공으로 표시하지 않는다.

기존 웹 작업실·규정 MCP·원본 RHWP 설치는 유지한다. 규정 MCP는 보조 편집 기능으로 남기며 Slack 파일 변환의 필수 경로로 두지 않는다. 텍스트 Markdown은 표의 열/셀 병합·그림·서명·쪽 배치를 보존하지 않고 OCR는 하지 않는다. Mac 실행 환경의 여유 공간과 지속 실행 상태는 실제 배포 시 확인한다.
