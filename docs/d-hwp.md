# D-HWP 사용·개발 안내

## 제품 범위
D-HWP는 RHWP for Slack을 기반으로 한 동국 한글문서 도우미 시제품이다. 문서 편집과 AI 요청문 준비를 제공한다. AI 답변·실제 지급/세무 판단·업무 자동승인 기능은 포함하지 않는다.

## 두 실행 경로
| 경로 | 진입 | 문서 처리 | 설정 |
|---|---|---|---|
| 로컬 작업실 | npm run desk → /desk/ | 브라우저 메모리, 사용자 직접 다운로드 | AI 키·Slack 로그인 불필요 |
| Slack 편집기 | Slack 문서 카드 → /editor/ | 기존 인증 서버·변환 서버·Slack 저장소 | 기존 .env/앱 설치 설정 필요 |

로컬 작업실 서버는 127.0.0.1에만 바인딩한다. 문서 업로드 API는 없으며 GET/HEAD로 프로그램 자산만 제공한다. CSP는 같은 출처의 프로그램·폰트·WASM 로딩만 허용한다. 문서와 요청문을 자동 전송하거나 localStorage/IndexedDB에 저장하지 않는다. 직접 복사·다운로드 후 다른 AI에 붙여넣는 행위는 사용자가 선택한 서비스의 처리 경로를 따른다.

## 문서와 AI 요청문
1. 파일을 열어 원문을 확인하고 필요한 부분을 수정한다.
2. 업무 패널의 전체 가져오기를 누르거나 필요한 부분만 붙여넣는다. 전체 가져오기는 선택 영역과 다르다.
3. 목적·추가 맥락을 지정하고 요청문을 만든다. 요청문에는 원문이 포함된다.
4. 미리보기에서 불필요한 정보·누락·표 구조를 확인한다.
5. 복사/Markdown 다운로드 후 사용이 허용된 AI에 직접 전달한다.

업무 목적은 요약, 공문 교정, 재무 검토 준비, 인수인계 네 가지다. 원문은 60,000자, 추가 맥락은 2,000자, 문서명은 200자까지 허용한다. 초과 입력은 조용히 잘라내지 않고 거부한다. 코드가 자동 익명화하거나 AI의 정확성을 보증하는 것은 아니다.

문서 내용을 가져온 뒤 문서가 바뀌면 다시 가져와야 한다. 원문·용도·문서명·추가 맥락이 바뀌면 이전 요청문은 무효화한다. 직접 붙여넣거나 수정한 텍스트는 편집기와 독립적인 입력이다. 전체 초기화는 패널의 입력·출력을 비우며 편집 중인 원본을 삭제하지 않는다.

## 구현 구조
- src/assistant/workflows.ts: 순수 요청문 생성, 입력 한도, JSON 참고자료, 파일명 정규화.
- src/assistant/panel.ts: 가져오기·미리보기·출력·초기화. DOM 값은 textContent/value 사용.
- src/desk/: 독립 로컬 작업실. 문서 교체·닫기·오류 시 기존 Studio와 패널 내용 정리.
- src/editor/: 기존 Slack 인증·새 파일 저장을 유지하면서 업무 패널 연결.
- scripts/build-desk.mjs, serve-desk.mjs: 별도 로컬 UI 빌드와 프로그램 자산만 제공하는 서버.

core/editor/Studio 0.8.7은 고정한다. SDK GetTextFile('TEXT','')를 전체 추출에 사용하며 saveblock을 선택 텍스트 추출로 사용하지 않는다. 문서 상태(documentEpoch/changeSeq/SHA)를 재확인해 가져온 텍스트가 오래된 경우 요청문 생성/내보내기를 막는다.

## 저장과 검증
편집본 다운로드는 새 파일을 생성하며 원본을 덮어쓰지 않는다. 브라우저의 다운로드 요청만으로 사용자의 디스크 저장 성공을 확정하지 않는다. 중요한 문서는 실제 다운로드 파일을 다시 열어 내용과 서식을 확인한다. 자동저장·이전 문서 복구는 제공하지 않는다.

로컬 작업실은 운영 서비스가 아니다. 교내 확장 전에는 대표 서식 10~20종의 호환성, 개인별 접근권한, 처리 서버/보관 범위, 운영 담당과 비용, 기존 방식 대비 작업시간을 확인한다. 기존 site/와 운영 문서에 있는 upstream 주소·운영자 정보는 새 서비스 설정으로 재사용하지 않는다.

## 라이선스와 출처
LICENSE와 THIRD_PARTY_NOTICES.md를 유지한다. 로컬 서버는 /licenses/MIT.txt 및 /licenses/THIRD_PARTY_NOTICES.md로 원문을 제공한다. upstream 엔진을 직접 수정하지 않고 호스트 UI로 기능을 확장한다.
