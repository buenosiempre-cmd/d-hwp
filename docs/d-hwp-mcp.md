# D-HWP 규정 MCP 연결

D-HWP의 규정 패널은 실제 MCP를 조회하여 규정 인용, 관련 조문, 재무 검토에 필요한 질문을 표시한다. 문서 편집은 기존 RHWP를 사용한다. 규정 결과는 AI가 생성한 답변이 아니며, 실제 AI 서비스 호출은 포함하지 않는다.

## 시작하기

Node 24.21.0 / npm 11.19.0과 기존 빌드 준비를 마친 뒤 저장소 루트에 `.env.desk.local`을 만든다. 이 파일은 Git에서 제외된다. `npm run desk` 또는 빌드 후 `npm run serve:desk`가 자동으로 읽는다. 브라우저에는 MCP 인증정보를 넣지 않는다.

### 방법 1: 로컬 MCP 프로세스

동국규정 MCP의 검증된 릴리스 또는 로컬 checkout을 준비한다. 예시는 경로를 실제 설치 위치로 바꿔 사용한다. D-HWP가 MCP를 대신 설치하거나 임의 명령을 받지는 않는다.

```dotenv
DHWP_RULES_MCP_COMMAND=node
DHWP_RULES_MCP_ARGS='["/absolute/path/dongguk-rule-mcp/src/index.js","--profile","rules"]'
```

각 조회는 MCP 프로세스를 실행해 요청하고 닫는다. 서버는 필요한 기본 환경과 `DONGGUK_*`, 선택 법령 연결 환경만 자식 프로세스에 전달한다. Slack·AI 인증정보를 통째로 전달하지 않는다. MCP 자체의 공개 규정 캐시 정책은 해당 프로젝트 설정을 따른다.

### 방법 2: 원격 MCP

```dotenv
DHWP_RULES_MCP_URL=https://dgu.kr-univ-rules.com/mcp/rules
DHWP_RULES_MCP_TOKEN=운영자가_발급한_접근범위에_맞는_인증정보
```

실제 인증정보는 로컬 설정이나 서버의 비밀 저장소에만 넣는다. stdio 설정과 URL 설정은 동시에 지정하지 않는다. 원격 주소는 HTTPS를 사용하며 로컬 테스트만 loopback HTTP를 허용한다. 리다이렉트는 따라가지 않는다. 현재 지원하는 원격 인증은 서버에 설정한 Bearer이며 브라우저 OAuth 로그인은 구현하지 않았다.

### 재무 검토와 Slack의 선택 활성화

재무 검토는 MCP의 `finance` 프로필과 D-HWP의 다음 설정을 함께 사용한다.

```dotenv
DHWP_RULES_FINANCE_ENABLED=true
```

내장 출장비·외부 강사료 질문 흐름은 내부 지식팩 없이 사용할 수 있다. 내부 업무 카드·지식팩과 한국법령 연결은 MCP에서 별도로 설정한다. 연결 정보의 ‘설정됨’은 실제 원문 조회 성공이나 업무 적용 확정이 아니다.

Slack 서버의 `.env`에는 같은 MCP 설정과 `DHWP_RULES_SLACK_ENABLED=true`를 넣어야 한다. 기본적으로 Slack MCP 기능은 비활성화되어 있다. 운영자가 해당 Slack 사용자에게 허용할 MCP 프로필과 내부 자료 접근 범위를 먼저 설정한다. 기존 Slack 문서 세션·문서 접근권한을 조회 전·후 다시 확인한다. 특정 사용자·그룹의 MCP 권한을 자동 동기화하는 기능은 없다.

## 사용 흐름

1. HWP/HWPX 문서를 열고 문서 전체 텍스트를 가져오거나 필요한 부분만 붙여넣는다.
2. ‘규정·법령 근거 확인’의 ‘규정 MCP 연결 확인’을 실행한다. 이 동작은 문서 본문을 보내지 않는다.
3. ‘규정 검토 방식’과 캠퍼스 등 조건을 지정한다. ‘전송할 내용 확인’을 읽고 동의 체크 후 ‘규정 검토 실행’을 누른다.
4. 인용 결과와 관련 조문·개정본·원문 링크, 부분 조회·미확정 상태를 확인한다.
5. ‘이 근거를 요청문에 포함’을 선택하고 ‘AI 요청문 만들기’를 누른다. 요청문 복사·Markdown 다운로드는 기존 기능을 이용한다. 근거는 조회 결과 전체를 포함하며 30,000자를 넘으면 조회 범위를 줄여 다시 확인한다.

인용 점검은 입력 텍스트를 보낸다. 규정 조회는 검색 질문·캠퍼스·선택 규정 번호를 보낸다. 재무 검토는 화면에 표시된 질문·사실관계와 선택한 텍스트를 보낸다. 조회 버튼을 누르기 전에는 문서 본문을 MCP로 자동 전송하지 않는다. 앱은 요청·응답 본문을 자동 저장하지 않으며 서버와 MCP 운영 환경의 보관 정책은 별도로 확인해야 한다.

## 결과 해석과 범위

- 인용 점검은 최신 개정본을 기준으로 규정·조문·제목·항을 대조한다. 인용이 실존한다는 것과 해당 업무에 적용된다는 것은 다르다.
- 인용 없음·미검사·잘림·부분 조회·확인 필요를 검토 통과로 표시하지 않는다. 원문 근거 상태와 업무 판단을 구분한다.
- 기준일이 필요한 재무 검토는 누락 질문부터 채운다. 일반 인용 점검에는 과거 기준일 검증을 지원하지 않는다.
- 캠퍼스는 업무 맥락이며 공식 규정 목록의 자동 캠퍼스 필터가 아니다. 적용범위는 원문에서 확인한다.
- 규정 검토 텍스트는 20,000자, 질문은 2,000자, 각 사실관계는 120자까지다. 초과 입력은 자르지 않고 거부한다. 기존 문서 요청문 원문 60,000자 한도와 다르므로 필요한 검토 범위를 사용자가 줄인다.
- 문서·입력·검토 조건이 바뀌면 이전 근거와 요청문을 무효화한다. 처리 중 늦게 도착한 결과도 반영하지 않는다.
- 서식·쪽·셀 위치를 자동으로 수정하지 않는다. 원문을 대조하고 검토 메모를 활용한다.

## 연결 오류

| 표시 | 확인할 내용 |
|---|---|
| 연결 설정 없음 | `.env.desk.local` 생성 후 로컬 서버 재시작 |
| 설정 오류 | stdio/URL 중 하나만 선택, args JSON 배열·URL 형식 확인 |
| 조회 시간 초과/연결 실패 | MCP 프로세스·공식 원문 서버·권한 확인 후 재시도 |
| 재무 기능 비활성 | finance 프로필과 D-HWP의 명시적 활성화 확인 |
| 내부 자료 미연결 | 해당 기능에 필요한 비식별 지식팩을 MCP 운영 설정에 연결 |
| 후보 여러 개 | 정확한 규정명 또는 규정 번호를 지정 |
| 문서 변경됨 | 현재 문서를 다시 가져와 새로 검토 |

오류가 나도 문서 열기·편집·다운로드는 계속할 수 있다. 오류 메시지에는 서버 주소의 인증정보·자식 프로세스 stderr·원시 예외를 포함하지 않는다.

## 구현과 검증

공유 계약은 `src/shared/rules.ts`, MCP client는 `src/server/rules-mcp.ts`, HTTP 경계는 `src/server/rules-api.ts`, 화면은 `src/assistant/rules-panel.ts`에 있다. SDK는 `@modelcontextprotocol/sdk` 1.32.1로 고정했다. MCP 도구는 서비스 정보·인용 점검·규정 조회·재무 검토 네 가지로 제한한다.

단위 테스트는 합성 MCP 서버로 stdio/HTTP·잘못된 입력·오류·응답 크기를 확인하고, API 검사는 출처·세션·권한·동시 요청을 확인한다. 브라우저 검사는 전송 확인·결과 표시·근거 요청문·변경 경합을 확인한다. 실제 동국규정 MCP 확인은 개인정보 없는 합성 문장으로 별도로 수행하며 자동 fixture 검사와 구분한다.

기반: [동국규정 MCP v0.12.0](https://github.com/buenosiempre-cmd/dongguk-rule-mcp/releases/tag/v0.12.0), [MCP TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk).
